# 🎼 Martestro (마르테스트로)

**Mart + Maestro · 오늘의 요리 지휘자**

우리 동네 마트의 이번 주 전단 할인 재료를 모아서 **"오늘 이 재료로 뭐 해 먹지?"** 에 답해 주는 무료 웹앱이에요.
설치 없이 링크만 열면 돼요 → **https://koonyang.github.io/martestro/**

- 📍 현재 위치(또는 동네 이름)로 주변 마트를 거리순으로 찾아요
- 🏷️ 선택한 마트의 전단 할인 재료를 보여 줘요 (행사 기간이 지난 건 자동으로 숨김)
- 🍳 할인 재료를 많이 쓰는 레시피를 절약액 순으로 추천해요 (레시피 1,000여 개)
- ✍️ 전단이 없는 동네 마트는 매장에서 본 할인 상품을 직접 적어 둘 수 있어요 (내 기기에만 저장)
- 🔄 전단 데이터는 **매일 새벽 5시(한국시간)** GitHub Actions 가 자동으로 새로 읽어 와요

> 휴대폰에서 `https` 링크로 열면 「현재 위치로 찾기」가 동작해요. 위치 권한이 싫으면 동네 이름이나 주소를 입력하면 돼요.
> 위치 정보는 주변 마트 검색(OpenStreetMap)에만 쓰고 어디에도 저장·전송하지 않아요(브라우저에만 저장).

### 내 주변 마트 찾기 (빠른 검색)
- 매주 월요일 03:30 KST 에 `scripts/build_marts.js` 가 OpenStreetMap(Overpass, 안 되면 Geofabrik 추출본 + osmium)에서 전국 마트를 받아요.
- 0.1°(약 11×9km) 격자로 나눠 `data/marts/s/<타일>.json`(마트), `data/marts/c/<타일>.json`(편의점), 전국 대형마트는 `data/marts/big.json` 한 파일로 저장해요. 비식품 가게 거르기는 이때 미리 해요.
- 앱은 내 위치 주변 타일 몇 개(수 KB)만 받아 거리 계산만 하므로 반경을 5km로 넓혀도 바로 나와요. 받은 타일은 브라우저가 캐시해요.
- 타일을 못 받으면 예전처럼 Overpass 실시간 검색으로 대신해요.

### 매일 하는 일 (`.github/workflows/update-deals.yml`)
1. 매일 05:00 KST(또는 Actions 탭에서 **Run workflow**)에 `scripts/update_deals.js` 실행
2. 마트별로 전단을 새로 읽어 `data/deals.json` 갱신
   - 어떤 마트가 실패하거나(사이트 구조 변경 등) 너무 적게 읽히면 **그 마트는 직전 데이터를 그대로 유지**
   - 행사 기간이 끝난 품목은 삭제
   - 탑마트는 전단이 바뀌었을 때만 OCR 을 돌려요 (같은 전단이면 그대로)
3. `scripts/build.js` 로 `index.html`(데이터 예비본 내장)을 다시 만들고 `test/test.js` 통과 확인
4. **실제로 바뀐 게 있을 때만** 커밋하고 GitHub Pages 에 배포

앱은 열릴 때 `data/deals.json` 을 받아 최신 데이터로 바꿔 끼우고, 못 받으면 `index.html` 에 들어 있는 예비본을 써요.
페이지 맨 아래 「출처·데이터 정보」를 열면 맨 위에 마트별 마지막 수집 상태(✅ 자동 수집 / ⚠️ 실패 → 이전 데이터)가 나와요.

### 간편식품 · 레시피 종류 필터
- 전단의 가공·즉석 식품(즉석밥·라면·만두·냉동식품·밀키트·햄/소시지/참치캔·즉석국/죽·카레/짜장·떡·어묵·맛살·우동면)은 `data/deals.json` 행의 10번째 칸에 `"간편식품"` 표시를 달아요(앞 9칸은 그대로라 예전 형식과 호환). 판정 규칙은 `src/logic.js` 의 `CONV_RULES`. 참치액·육수 같은 양념과 냉동 생고기·수산물은 제외해요.
- 라면·만두·햄·소시지·참치·어묵·맛살·카레·떡·우동면은 레시피 재료와 바로 매칭되고, 즉석밥은 「지은 밥」이 필요한 레시피의 쌀 자리에 매칭돼요. 할인 재료 탭에서는 「간편식품」 한 묶음으로 보여요.
- 레시피 추천 탭의 [전체] [자취생] [간편식품] 칩 (자취생·간편식품은 함께 고르면 합집합):
  - **자취생**: 후식·기타가 아닌 끼니 요리 + 재료 줄(양념 포함) 7개 이하(기본 레시피는 재료 5개 이하·주재료 2개 이하) + 비싼 재료(소고기·전복·갈치·연어·문어 등) 없음.
  - **간편식품**: 위 가공·즉석 식품이 주재료인 요리(기본 레시피는 부재료여도), 지은 밥(=즉석밥)으로 만드는 요리 (후식 제외). 조리시간은 쓰지 않아요.

### 직접 쓴 추가 레시피와 사진
- `src/hand_recipes.js` 에 자취·간편식 위주 집밥 레시피 52개를 직접 써서 넣었어요 (레시피 사이트 문장 복사 없음). 전단에 자주 나오는 돼지고기·닭·두부·계란·콩나물·애호박·대파·어묵·참치·햄·만두·라면·우동면 위주이고, 공공 레시피 983개·기존 43개와 이름이 겹치지 않아요.
- 형식은 기존 기본 레시피와 같아요: `[이름, 이모지, 분류, 인분, [[재료키, 주재료여부, 분량]…], 만드는 법, 사진 slug]`. 인분(1 또는 2)을 직접 적어 한 끼 분량을 계산하고, 열량은 재료 분량으로 어림해요. 자취생·간편식품 태그는 위 규칙 그대로 자동으로 붙어요.
- 사진은 `assets/recipes/<slug>.webp` (640×480, WebP q72, 장당 14–60KB).
  - **실제 사진 20장**: 위키미디어 공용(Wikimedia Commons)의 CC0 / 퍼블릭 도메인 / CC BY / CC BY-SA 사진만 썼어요. 크기를 줄이고 4:3으로 잘랐어요. 원본 제목·작가·라이선스·링크는 `HAND_IMG_CREDIT` 에 있고 앱의 「출처·데이터 정보」 → 「레시피 사진」에 모두 표시해요.
  - **AI 생성 이미지 32장**: 맞는 자유 이용 사진이 없는 요리는 AI로 만든 이미지를 쓰고, 카드 사진과 자세히 사진 아래쪽 가운데에 작게 「AI 생성 이미지」라고 표시해요 (「주재료 n/m 할인 중」 막과 겹치지 않아요). 실제 사진에는 표시가 없어요.

### 레시피 열량 (kcal)과 정렬
- 공공 레시피(식품안전나라)는 데이터에 있는 1인분 열량을 그대로 보여 줘요. 다만 5kcal 미만·1,200kcal 초과(예: 클럽 샌드위치 1kcal, 배추 달걀볶음 1311kcal)는 데이터 오류로 보고 열량 없음으로 둬요.
- 직접 다듬은 기본 레시피 95개는 열량 데이터가 없어서 **재료 분량으로 어림**해 「약 410kcal」처럼 보여 줘요 (조리시간 표시는 없앴어요):
  - 재료 분량(g, 아래 「한 끼」 가격과 같은 변환) ÷ 인분(기본 2인분, 밥 1공기 요리는 1인분) × 100g당 열량(국가표준식품성분표 값을 반올림한 대략값, 예: 돼지고기 250·삼겹살 330·소고기 200·두부 85·계란 140·생쌀 360·감자 70·양파 35·김치 20·라면 450·떡 230·참기름 900).
  - 뼈·껍질째 무게인 닭 1마리·생선 1마리는 먹는 부분만큼 낮춘 값(닭 125, 고등어 120)을 써요. 분량을 못 읽으면 재료별 1인분 기본값.
  - 볶음·구이·말이·전엔 식용유 1큰술, 전엔 밀가루, 조림·불고기·제육·떡볶이·잡채엔 설탕·물엿, 맛탕엔 시럽을 조금 더해요. 10kcal 단위로 반올림해요.
  - 실제 열량은 조리법·분량에 따라 꽤 달라질 수 있는 어림값이에요.
- 레시피 정렬: 추천순 · 절약률 · 예상 비용(한 끼) · 칼로리 (다시 누르면 낮은순↔높은순). 열량이 없는 레시피는 어느 방향이든 맨 뒤예요. 예전에 저장한 조리시간 정렬은 추천순으로 바뀌어요.

### 레시피 카드의 「한 끼」 가격 (가정)

레시피 카드의 재료 가격은 팩 전체 가격이 아니라 **한 끼(1인분)에 쓰는 만큼**으로 보여 줘요. 할인 재료 탭은 실제 팩 가격 그대로예요.

- **팩 크기**: 전단 상품명에서 읽어요. `1kg`·`500g`·`900ml`·`137g×4입`·`500g+500g`처럼 무게가 있으면 그대로, `30구`·`6~8입`·`3마리`·`(개)`·`(단)`·`(통)`처럼 개수만 있으면 재료별 한 개 무게로 바꿔요 (예: 계란 55g, 양파 200g, 대파 1단 800g, 고등어 1마리 400g, 오징어 250g, 닭 1마리 1kg).
- **100g당 가격**(정육·수산 `100g` 표기)은 단가로 보고 쓰는 양만큼 곱해요 (150g이면 ×1.5).
- **한 끼 사용량**: 공공 레시피(식품안전나라)는 1인분 기준 g 표기라 재료 줄의 g을 그대로 써요. 직접 다듬은 기본 레시피는 2인분으로 보고 분량을 반으로 나눠요 (밥 1공기가 들어간 볶음밥·덮밥은 1인분). `1/2모`·`1대`·`2큰술`·`한 줌`·`약간` 같은 표기도 g으로 바꿔요 (큰술 15g, 작은술 5g, 컵 200g, 한 줌 50g, 약간 5g, 두부 1모 300g, 김치 1포기 2.5kg 등).
- 분량을 못 읽으면 **재료별 1인분 기본값**을 써요: 고기 150g(닭 200g), 생선 150g, 오징어 120g, 새우 80g, 두부 반 모(150g), 계란 1~2개(80g), 채소 50~150g(양파 80g, 감자 150g, 대파 30g, 마늘 10g), 라면 1봉(120g), 생쌀 90g(밥 1공기), 즉석밥 1개, 양념(된장 20g, 고추장 15g, 참기름 5g)은 아주 적게. 소스·곁들임까지 합쳐 너무 커지지 않게 기본값의 2.5배까지만 써요.
- **한 끼 가격** = 팩 가격 × (한 끼 사용량 ÷ 팩 무게), 10원 단위로 반올림해 「한 끼 약 1,240원」처럼 보여 줘요. 생쌀 상품과 지은 밥 상품(햇반 등)은 1공기 90g/210g으로 따로 계산해요.
- 팩 크기를 못 읽는 상품(예: `(각)`, `(팩)`, `상품별 규격 상이`)은 팩 가격에 작은 **「1팩 기준」** 표시를 붙여요.
- **절약률 게이지**도 같은 한 끼 분량으로 원가 → 할인가를 더해 「한 끼 기준」이라고 표시해요 (팩 크기를 모르는 재료가 섞이면 「일부 1팩」). **비용 낮은순** 정렬도 이 한 끼 비용(주재료 합)을 써요. 추천 순위 계산은 그대로예요.
- 실제 장보기는 팩 단위라 남는 재료가 생겨요. 한 끼 가격은 「이 요리에 드는 몫」을 어림한 값이에요.

## ⚠️ 알아 두세요
- 전단 가격은 **행사 기간·점포·회원/카드 조건**에 따라 달라요. 장보러 가기 전에 마트 앱이나 매장에서 꼭 확인하세요.
- 이 앱은 각 마트와 관계없는 개인 프로젝트예요. 마트 이름·상표·전단 내용의 권리는 각 회사에 있어요.
- 자동 판독(OCR)·자동 분류(어떤 재료인지 추정)는 틀릴 수 있어요.
- 마트 사이트 구조가 바뀌면 그 마트 자동 갱신이 멈출 수 있어요 (그동안은 직전 데이터 → 기간이 끝나면 비어 보임).

## 폴더 구조
```
index.html              빌드된 앱 (GitHub Pages 가 이 파일을 보여 줌)
data/deals.json         전단 할인 데이터 (매일 자동 갱신)
data/marts/             전국 마트 위치 타일 (매주 자동 갱신)
src/template.html       화면(HTML/CSS/UI 코드)
src/logic.js            재료 판별·레시피 추천 로직 (브라우저/Node 공용)
src/pub_data.js         식품안전나라 레시피 (scripts/build_pub.js 로 생성)
src/hand_recipes.js     직접 쓴 추가 집밥 레시피 52개 + 사진 출처
assets/recipes/         추가 레시피 사진 (640×480 WebP)
scripts/update_deals.js 전단 갱신 실행기
scripts/scrapers/       마트별 수집기 (emart, homeplus, lottemart, topmart, cu, seven, emart24 + cvs_common)
scripts/build.js        src + data → index.html
scripts/build_marts.js  OpenStreetMap → data/marts 타일
test/                   로직 테스트(test.js), 브라우저 확인(browser/smoke.js)
```

## 직접 돌려 보기 (개발자용)
Node 18 이상, 외부 패키지 없음.
```bash
node scripts/update_deals.js   # 전단 새로 읽기 (탑마트 OCR 은 tesseract + 한국어 데이터 필요: apt install tesseract-ocr tesseract-ocr-kor)
node scripts/build.js          # index.html 만들기
node test/test.js              # 테스트
npx serve .                    # 아무 정적 서버로 열어 보기 (file:// 로 열면 내장 예비본 사용)
```
레시피 데이터를 다시 만들려면 식품안전나라 COOKRCP01 응답(JSON row 배열)을 `raw/all.json` 에 저장한 뒤 `node scripts/build_pub.js` (raw/ 는 용량이 커서 저장소에 넣지 않아요).
